# 黏黏吞噬史 · Demo 设计文档

> 一滩史莱姆把人类文明一口一口吞掉。它吞下的每一件东西，都是 Hi3D 今天生成的。

本文件记录盘问阶段达成的共识，写代码以此为准。改设计先改这里。

## 术语

| 术语 | 含义 |
|---|---|
| 史莱姆 | 玩家角色，代码生成的霓虹果冻（不占 Hi3D 额度） |
| 物件 | 地图上可被吞噬的 Hi3D 模型，每个有固定"体重"（kg） |
| 体重 | 史莱姆和 Boss 共用的数值；史莱姆的体重即成长，Boss 的体重即血量 |
| 档位 | 每关内 3 个体型门槛，每升一档可吞更大的物件 |
| 强化卡 | 升档时弹出的三选一卡片 |
| 膨胀 | 普通史莱姆的主动技能 |
| 祭坛 | 地图中央召唤 Boss 的地点 |
| 垃圾车怪兽 | 现代地图的 Boss |

## Demo 范围

- **只做现代地图**，加上垃圾车怪兽 Boss。
- 不限时，没有失败惩罚。
- 挂起：其他时代（石器、古代、未来）、解锁角色、演示模式。
- 不做：排行榜、野生史莱姆。

## 操作

| 平台 | 移动 | 技能 |
|---|---|---|
| 电脑 | WASD 或方向键 | 空格 |
| 手机（竖屏优先） | 在屏幕任意处按住拖动（浮动摇杆） | 右下角按钮，带冷却转圈 |

全程是平面移动，没有跳跃，也没有冲刺。

## 核心循环

1. 碰到比自己小的物件，把它裹进身体。物件在半透明的身体里旋转、溶解，史莱姆随之变大。
2. 碰到比自己大的物件会被弹开，没有其他惩罚。
3. 体重越过档位门槛时：大字提示"现在能吞：X、Y！"，镜头拉远一档，弹出强化卡。
4. 地图剩余物件少于 30% 时，在边缘补刷一批中小型物件（"文明重建中…"）。
5. 随时可以去祭坛召唤 Boss。吞掉 Boss 后进入结算。

## 技能：膨胀

- 3 秒内体型变成 1.5 倍，能吞平时吞不下的物件。冷却时间暂定 8 秒。
- 膨胀期间撞 Boss，伤害 ×2。
- 能否吞噬 Boss **按真实体重判断，不算膨胀**。

## 强化卡

卡池：吸附范围、移动速度、溶解速度、可吞尺寸、膨胀冷却、膨胀时长、撞击 Boss 伤害。

弹出时游戏暂停，3 张卡竖排，点一下就选；5 秒不选就自动随机选一张。

## Boss：垃圾车怪兽（最简版）

1. **召唤**：爬上祭坛，弹出面板「Boss ×× kg / 你 ×× kg」和一个"召唤"按钮，面板按差距显示红、黄、绿。红色也允许召唤。
2. **招式只有一个，倒车冲撞**：先响"哔哔哔"倒车警报，地上出现红色长条预警，然后冲过来。冲过头会撞晕 2 秒。
3. **碰撞伤害**：任何时候碰到它，它都会扣血（掉体重），并掉出一点可以吃的垃圾。每次碰撞后约有 1 秒间隔，扣血量和玩家体重成正比。撞晕的 2 秒是放心撞它的时机。
4. **被冲撞撞中**：玩家弹飞，并吐出几个吞下的物件（可以再捡回来）。
5. **胜利**：Boss 体重低于玩家时，碰到它就整个吞掉，配慢镜头和"吞噬！"大字，然后进入结算。
6. Boss 战在全地图进行，期间镜头自动拉远，把双方都框进画面。

结算画面：用时、最终体重，再加一句"全部物件由 Hi3D 生成"。画面要适合截图分享。

## 界面

剩余物件数、正计时、左下角大号 kg、技能按钮、拟声词飘字（"+1 噗！"）、事件横幅，以及音效。

## 画风

- 低多边形、平涂色块、明亮饱和配色。参考：玩具城风格。
- 现代地图用黄昏光照。史莱姆是光滑有光泽的霓虹果冻。
- 地面、道路、树木等填充物用代码生成。
- 出图统一使用下面这句风格描述词，只替换〔〕里的物体：

> 「一个〔物体〕，低多边形 low-poly 卡通风格，平涂色块，简洁块面造型，明亮饱和配色，单个物体居中，纯白背景，45 度俯视角，无投影，无文字」

## 素材（10 个 Hi3D 模型，从小到大）

垃圾桶、消防栓、路灯、长椅、自行车、报刊亭、汽车、公交车、楼房，以及垃圾车怪兽（Boss）。

## Hi3D 流水线

- 接口只支持图生 3D，图片必须是公网网址。原图放在仓库的 `raw-images/` 文件夹，用 raw.githubusercontent.com 的网址提交。
- 参数：`hitem3dv2.0`，分辨率 `1536`，`request_type=3`，面数约 5 万。测试图同时用来确认 `format` 参数的含义。
- 下载后用 gltf-transform 处理：减到约 5000 面，贴图 512px。
- 测速后按下面的规则决定：
  - 单个 ≤ 8 分钟：全部用 Hi3D。
  - 8–20 分钟：全部提交，先用占位模型推进开发。
  - 超过 20 分钟或生成失败：只保 Boss 和少数几个物件，讲稿相应调整。
- 积分：共 1100。测试图记录单次消耗，每个物件最多重抽 1 次。
- 没有模型的物件先用代码生成的占位模型，保证游戏随时都能玩。

## 技术

- Three.js 网页游戏，用 GitHub Pages 部署，观众扫码就能玩。
- 物件、档位、卡片、角色、技能全部写在配置数据里，以后加新史莱姆只需要加一条配置。
- 性能预算：首屏 ≤ 3 MB，全部模型 ≤ 12 MB，中端安卓 ≥ 45 帧，用实例化渲染。
